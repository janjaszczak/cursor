# SearXNG (self-hosted search) for MCP

This folder configures a **local, free, keyless** search engine used as the
default web-search backend for Cursor agents, replacing paid per-request
search (Perplexity) for routine lookups.

## Architecture (2 containers, same pattern as `mcp-memory` + Neo4j)

```
searxng (searxng/searxng:latest)   ← engine container, started by scripts/start-searxng.sh
   │  http://searxng:8080 (mcp-network) / http://localhost:8080 (host, for debugging)
   ▼
mcp-searxng (isokoliuk/mcp-searxng) ← MCP wrapper, started on-demand by Cursor via mcp.json "searxng" entry
```

- **`searxng`** is the actual metasearch engine (aggregates Google, Bing,
  Brave, DuckDuckGo, Wikipedia, etc.). It must be started **once, separately**
  (like the `neo4j` container for the `memory` MCP server) — Cursor does not
  start it for you.
- **`mcp-searxng`** is a thin MCP protocol wrapper published by
  [ihor-sokoliuk/mcp-searxng](https://github.com/ihor-sokoliuk/MCP-searxng)
  (Docker Hub: `isokoliuk/mcp-searxng`). It is a public, pre-built image —
  no custom Dockerfile needed here, unlike `mcp-duckduckgo`/`mcp-memory`.

## One-time setup

```bash
./scripts/start-searxng.sh
```

This creates the `mcp-network` Docker network (idempotent, shared with the
`memory` MCP server), generates a random `SEARXNG_SECRET` if one is not
already set in your environment, and starts the `searxng` container bound to
`127.0.0.1:8080` (host) and `mcp-network` (for the MCP wrapper).

Then restart Cursor so it picks up the `searxng` entry from `mcp.json`.

## Files

- **`settings.yml`** — mounted read-only into the `searxng` container at
  `/etc/searxng/settings.yml`. Enables the `json` output format (required by
  the MCP wrapper — without it SearXNG returns `403` for API requests) and
  disables the bot/rate limiter (safe because this instance is never exposed
  to the public internet).

## Verifying it works

```bash
# Engine reachable and JSON format enabled:
curl -s "http://localhost:8080/search?q=test&format=json" | head -c 200

# Container healthy:
docker logs searxng --tail 50
```

If `format=json` returns `403`, double-check `search.formats` in
`settings.yml` includes `json` and that the container picked up the mounted
file (`docker inspect searxng --format '{{ json .Mounts }}'`).

## Environment variables

| Variable | Required | Purpose |
|---|---|---|
| `SEARXNG_SECRET` | Auto-generated by `start-searxng.sh` if unset | CSRF/session secret for the engine. Low sensitivity (not protecting external data) since the instance is local-only. |

No API keys are required — this is the whole point (zero marginal cost per
search, vs. Perplexity's per-request + token pricing).

## When to still use `perplexity` instead

SearXNG returns raw search results (titles/URLs/snippets) — the agent itself
synthesizes the answer, same as for `duckduckgo`. Prefer `perplexity` only
when the user explicitly asks for deep research / high-stakes verification
where a single-call synthesized answer with citations is worth the per-request
cost (see `skills/deep-research/SKILL.md`).
